# PromptWordSplicer 产品路线清单

## 目标

这份清单用于收束当前阶段的产品改进方向，避免功能扩散。排序原则只有四条：

- 服务单人高频使用
- 强化批量生产能力
- 保持人工控制优先
- 让 AI 执行成为增效层，而不是主导层

## 判断原则

- 优先做直接影响日常效率的能力
- 优先做能增强变量、步骤、批量任务关系的能力
- 避免过早做重型平台化功能
- 避免把产品推成自动 Agent 编排器

## 必须做

这些能力最接近当前产品定位，且完成后会显著提升实际使用效率。

### 1. 批量实例化与变量表导入导出

- 支持用一份模板批量生成多个项目实例
- 支持从 `CSV / JSON` 导入变量表
- 支持将当前项目变量导出成可编辑表格

价值：
这项能力直接对应“提示词大部分相同，只有少量变量不同”的核心场景，是产品从单项目工具走向批量工作台的关键一步。

### 2. 执行配置模板库

- 把常用的 `模型引用 + temperature + maxTokens + system prompt` 存成命名方案
- 步骤可直接套用执行配置模板，而不是依赖复制旧步骤

价值：
比“复制执行配置”更稳定、更可维护，能沉淀长期可复用的 AI 执行经验。

### 3. 结构化输出与输出拆变量

- 支持为某些步骤定义结构化输出格式
- 支持把一次 AI 输出拆成多个变量
- 允许后续步骤直接引用拆分后的字段

价值：
这是变量系统从“存文本”升级到“存结构”的关键。没有这层，后续多步流程仍会有大量人工搬运。

### 4. 模板版本快照

- 每次保存模板时可留历史版本
- 支持查看差异与回滚

价值：
模板会越来越复杂，没有版本快照，后面只会越来越不敢改。

## 应该做

这些能力强相关，但紧迫度略低于上面四项。

### 5. 变量自动补全与引用跳转

- 输入 `{{...}}` 时自动列出可选变量
- 点变量引用可跳转到来源步骤或变量定义位置

价值：
会显著降低长流程模板的维护成本。

### 6. 批量执行某一步

- 在多个项目实例上批量执行同一个步骤
- 支持只重跑失败项

价值：
这项能力和批量实例化配合后，产品会更接近真正的批量 AI 生产台。

### 7. 步骤结果对比

- 同一步多次运行时，支持对比当前结果与历史结果
- 支持快速恢复某次历史版本

价值：
现在日志能看能回放，但还不够利于比较调参效果。

### 8. 模型配置健康检查

- 提示缺失 API Key 的 provider
- 提示失效或禁用的模型目录项
- 提示引用异常的模板步骤

价值：
这是设置层和模板层真正打通后的必要检查。

## 可以做

这些能力会提升体验，但不是当前阶段的第一优先级。

### 9. 项目视图增强

- 紧凑 / 详细视图切换
- 步骤搜索
- 最近打开项目 / 最近执行步骤

### 10. 快捷键体系

- 执行当前步骤
- 复制插值结果
- 写入变量
- 展开 / 折叠步骤

### 11. 项目运行快照

- 冻结某一轮项目状态
- 便于回看一次完整生成链的结果

### 12. 文档内联化

- 在应用内直接显示模板说明、项目说明和运行备注

## 暂缓

这些想法不是没价值，而是现在做会分散主线。

### 13. 可视化节点画布

当前产品更适合步骤流，不适合先做重型节点编排。

### 14. 多人协作与云同步

当前还是单人高频使用场景，优先级不足。

### 15. 模板市场与分享中心

模板资产还在快速演进阶段，先把内部结构做稳更重要。

### 16. 自动整链执行与分支决策

这会把产品推向 Agent 工作流平台，不符合当前“人工控制优先”的定位。

### 17. 插件系统

当前产品主干还在演化，过早开放插件会放大维护成本。

## 推荐推进顺序

如果按未来几轮迭代排序，我建议：

1. 批量实例化与变量表导入导出
2. 执行配置模板库
3. 结构化输出与输出拆变量
4. 模板版本快照
5. 变量自动补全与引用跳转
6. 批量执行某一步

## 结论

PromptWordSplicer 后面的价值，不在于继续堆更多模型接入，而在于把下面三件事做深：

- 批量任务能力
- 变量与步骤之间的结构化关系
- 人工控制下的 AI 执行效率

只要这三条主线稳定，这个产品就会从“顺手工具”升级成“真正可持续使用的本地 AI 生产工作台”。
