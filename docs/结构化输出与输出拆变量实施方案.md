# PromptWordSplicer 结构化输出与输出拆变量实施方案

## 1. 目标

当前项目已经能稳定完成：

- 模板化提示词管理
- 步骤执行与输出变量流转
- 生产节点自动化

但“步骤结果”仍主要是整段自由文本。对当前图像/视频提示词生产链来说，这有两个问题：

1. 下游步骤经常只需要其中一部分信息，而不是整段文本。
2. 批量导出、变量复用、后续自动化都会因为整段文本过于松散而变得不稳定。

因此，下一阶段的目标不是再增加更多模型，而是把“中间文本资产”从整段输出升级成可拆分、可引用、可导出的结构化结果。

本方案聚焦两件事：

1. 结构化输出
2. 输出拆变量

## 2. 适用场景

这个能力优先服务于如下步骤：

- 生成图片描述
- 生成风格词
- 生成镜头说明
- 生成构图说明
- 生成负面词
- 生成分镜文本

典型链路示例：

1. 用户输入基础设定和需求。
2. 语言模型生成一段结构化描述，例如：
   - 主体描述
   - 风格描述
   - 构图描述
   - 光影描述
3. 这些字段分别进入不同变量。
4. 下游步骤再按字段拼装最终生图提示词或生视频提示词。

本质上，它要解决的是：

“同一个步骤产出的文本资产，如何被多个后续步骤稳定复用，而不是靠整段长文本硬拼。”

## 3. 范围与边界

本轮只做结构化输出的第一阶段，不做以下内容：

- 不做蓝图式节点画布
- 不做图片/视频模型调用
- 不做 LLM 输出 JSON 自动强校验
- 不做 tool calling / function calling
- 不做复杂 schema 编辑器
- 不做结构化结果的自动版本合并

本轮只做：

- 模板层定义“期望输出字段”
- 项目层保存“字段化结果”
- 将字段映射到多个变量
- 下游步骤通过 `{{variable_key}}` 继续使用这些字段

## 4. 产品判断

这一阶段不要把“结构化输出”理解成严格的 API 契约，而应该把它理解成：

“对中间文本资产的半结构化整理能力”

也就是说：

- 用户仍然可以手动改结果
- 模型仍然可以先输出一段自由文本
- 但系统提供一层字段化承接
- 这些字段再继续流入变量系统

这样既能保持你现在的人控优先，又能为未来更深的自动化打基础。

## 5. 实施分期

建议拆成两个子阶段。

### 5.1 阶段 A：字段定义与手动承接

先让模板步骤声明：

- 该步骤期望产出哪些字段
- 这些字段是否要写入变量

项目页中先由用户手动填写或修正字段值。

这一阶段先不要求模型直接返回结构化 JSON。

### 5.2 阶段 B：结果解析与自动映射

在阶段 A 稳定后，再增加：

- 模型输出自动解析为字段
- 字段自动回填
- 字段自动同步到变量

也就是说，先把“结构”搭起来，再让 AI 自动填结构。

## 6. 数据结构方案

### 6.1 模板步骤新增结构化输出定义

建议在 `TemplateStep` 中扩展：

```ts
interface StructuredOutputFieldDefinition {
  key: string;
  label: string;
  description?: string;
  required?: boolean;
}

interface StructuredOutputVariableBinding {
  fieldKey: string;
  variableKey: string;
  variableLabel?: string;
}
```

在 `TemplateStep` 中新增：

```ts
structuredOutputFields?: StructuredOutputFieldDefinition[];
structuredOutputBindings?: StructuredOutputVariableBinding[];
```

语义如下：

- `structuredOutputFields`
  - 说明这个步骤希望产出哪些字段
- `structuredOutputBindings`
  - 说明某个字段应写入哪个变量

### 6.2 项目层新增结构化结果存储

建议在 `Project` 中新增：

```ts
stepStructuredOutputs?: Record<string, Record<string, string>>;
```

含义：

- 第一层 key：`stepId`
- 第二层 key：字段 key
- value：该字段当前值

例如：

```ts
stepStructuredOutputs: {
  "step-1": {
    subject_description: "...",
    style_keywords: "...",
    composition_notes: "..."
  }
}
```

### 6.3 保持现有字段不变

本轮不删除：

- `stepOutputs`
- `variables`
- `stepOutputMeta`

原因：

- `stepOutputs` 仍然适合作为整段原始结果缓存
- `stepStructuredOutputs` 是对其补充，不是替代
- 旧项目和旧模板必须兼容

## 7. 变量流转规则

结构化输出进入变量系统时，建议使用以下规则：

1. 若某字段配置了 `structuredOutputBindings`
   - 保存该字段值到对应变量
2. 若字段为空
   - 不覆盖已有变量
3. 若字段有值
   - 更新对应变量值
4. 变量来源类型建议标记为：
   - `structured_step_output`

如果当前变量来源枚举不方便直接扩展，也可以先继续沿用 `step_output`，但建议后续区分。

## 8. TemplateEditor 界面方案

### 8.1 执行配置区下方新增“结构化输出”

在步骤编辑区新增一个折叠块：

- 标题：`结构化输出`
- 默认收起

展开后包含两部分：

1. 字段定义列表
2. 字段到变量的绑定列表

### 8.2 字段定义交互

每个字段至少可编辑：

- 字段 key
- 显示名称
- 说明
- 是否必填

支持：

- 新增字段
- 删除字段
- 调整顺序

### 8.3 字段绑定交互

每个字段下可选是否绑定到变量：

- 不绑定
- 绑定到已有变量 key
- 绑定到一个新变量 key

绑定结果在摘要区显示为：

- `subject_description -> {{subject_description}}`

## 9. 项目页界面方案

### 9.1 步骤结果区新增“字段化结果”

当某步骤配置了 `structuredOutputFields` 时，项目页步骤卡片在结果区下面新增一个轻量折叠区：

- 标题：`字段化结果`
- 默认展开或默认收起，建议先默认展开

字段化结果区展示：

- 字段名称
- 当前字段值输入框
- 若已绑定变量，显示 `-> {{variable_key}}`

### 9.2 与整段结果并存

同一步骤中同时保留：

- 整段结果
- 字段化结果

整段结果用于：

- 保留原始模型输出
- 复制完整结果

字段化结果用于：

- 精确复用
- 后续变量流转

### 9.3 同步策略

阶段 A 先采用：

- 用户修改字段值时，立即同步到变量
- 不自动从整段结果反推字段

这样风险最小。

## 10. 与自动化流程的关系

这一能力和当前生产节点自动化并不冲突，关系如下：

1. 自动执行先产出整段步骤结果。
2. 若步骤配置了结构化字段：
   - 阶段 A：用户手动整理字段
   - 阶段 B：系统尝试自动解析字段
3. 字段值同步进变量。
4. 下游步骤继续引用这些变量。

所以结构化输出不是新的执行链，而是当前执行链的结果承接层。

## 11. 迁移与兼容策略

### 11.1 旧模板

旧模板默认：

- `structuredOutputFields = []`
- `structuredOutputBindings = []`

不受影响。

### 11.2 旧项目

旧项目默认：

```ts
stepStructuredOutputs = {}
```

不影响原有 `stepOutputs` 和变量系统。

### 11.3 读取优先级

后续若某处需要读取“步骤产出的变量值”，优先级建议为：

1. `structuredOutputBindings` 绑定后的变量
2. 原始 `outputBinding` 对应变量
3. 原始 `stepOutputs`

## 12. 实施顺序

建议按以下顺序推进：

### 阶段 1：数据层

1. 扩展 `types.ts`
2. 扩展模板和项目归一化逻辑
3. 扩展 schema 校验

### 阶段 2：模板层

1. `TemplateEditor` 增加结构化输出定义
2. 支持字段列表和字段绑定编辑
3. 摘要展示字段绑定关系

### 阶段 3：项目层

1. `ProjectRunner / ProjectStepCard` 增加字段化结果区
2. 支持字段值编辑
3. 修改字段时同步变量

### 阶段 4：联动优化

1. 在侧边栏变量区更好地展示结构化来源
2. 在自动化执行结果后增加“待整理字段”提示
3. 再考虑自动解析整段结果

## 13. 验收标准

完成后至少应达到：

1. 模板步骤可以定义结构化字段。
2. 模板步骤可以把字段绑定到多个变量。
3. 项目页可以编辑字段化结果。
4. 字段值变化能同步进对应变量。
5. 下游步骤可以通过 `{{variable_key}}` 使用这些字段。
6. 旧模板、旧项目不报错、不回归。

## 14. 风险与控制

### 14.1 认知负担风险

字段、变量、整段结果三层同时出现，容易变复杂。

控制方式：

- 默认折叠“结构化输出”区
- 先只在需要的步骤上启用
- 用摘要而不是大段说明

### 14.2 数据分叉风险

整段结果和字段结果可能不一致。

控制方式：

- 阶段 A 不自动解析，不强求一致
- 先把字段视为“人工整理后的可复用结果”
- 后续如果做自动解析，再补“重新生成字段”动作

### 14.3 兼容风险

增加结构字段后容易影响旧模板。

控制方式：

- 所有新字段可选
- 统一走 normalize
- 不替换旧字段，只增量补充

如果按当前节奏继续推进，建议下一份文档直接进入：

- 首轮只做阶段 A 还是同时做 A+B

- 当前变量来源类型是否新增枚举
