# PromptWordSplicer 步骤交互与模型引用重构方案

## 背景

当前项目已经具备步骤编辑、结果回填、变量引用和状态提示，但交互层仍然存在三类问题：

- 项目页步骤区操作重复，尤其是复制结果入口重复且折叠态不可见。
- 模板页执行配置按步骤重复暴露 `mode / provider / model`，配置负担过高。
- `推荐结果变量` 这套命名和 `mode` 配置不符合真实使用心智。

## 目标

本轮改动只做三件事：

1. 收紧步骤区高频操作，让 `复制结果` 在折叠态可见，去掉重复入口。
2. 用模板级 `模型引用` 替代步骤级 `provider/model/mode` 重复配置。
3. 把 `推荐结果变量` 改成 `输出到变量`，去掉多余的 `mode`。

## 方案

### 1. 项目页步骤交互

- 把 `复制插值结果` 提升到步骤头部，折叠态也可见。
- 把 `复制模板原文` 放到 `复制结果` 右侧，作为次一级操作。
- 删除正文区域重复的复制按钮。
- 删除输出区里重复的“手动写入变量”按钮。
- 只有步骤配置了 `输出到变量` 时，头部或正文中才允许出现写入变量按钮。

### 2. 模板级模型引用

新增模板级数据结构：

```ts
interface TemplateModelRef {
  id: string;
  label: string;
  presetId: string;
}
```

新增程序预设模型列表：

- 每个预设模型包含 `id / label / provider`
- 用户在模板中不直接填写 provider/model
- 用户只创建模型引用，再为引用选择一个预设模型

步骤级执行配置改为：

```ts
interface StepExecutionConfig {
  modelRefId?: string;
  systemPrompt: string;
}
```

含义：

- `modelRefId` 为空，步骤就是手动步骤
- `modelRefId` 不为空，步骤可使用该模型引用执行
- `systemPrompt` 仍保留在步骤级，用于区分不同步骤的执行角色

### 3. 输出到变量

步骤输出绑定改为：

```ts
interface StepOutputBinding {
  variableKey?: string;
  variableLabel?: string;
}
```

交互规则：

- `variableKey` 为空，即不绑定
- 不再需要 `mode = none | variable`
- UI 名称改为 `输出到变量`
- 当 `variableKey` 非空时，显示当前绑定 key
- 编辑时提示该 key 是“复用已有变量”还是“将创建新的输出变量”

## 实施顺序

1. 改 `types.ts` 和 `constants.ts`
2. 改模板编辑器：增加模型引用区，简化步骤执行配置和输出变量配置
3. 改项目页步骤头部操作，移除重复按钮
4. 验证核心前端文件类型检查

## 非目标

- 本轮不接真实模型调用
- 本轮不做模型密钥管理
- 本轮不做自动执行链
