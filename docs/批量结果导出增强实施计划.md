# PromptWordSplicer 批量结果导出增强实施计划

## Summary

这一轮只实现“批量结果导出增强”的第一版，不扩生图/生视频模型，不改生产节点自动化执行范围，不引入复杂导出模板系统。

首轮交付目标锁定为：

1. 在现有批量执行结果弹层中增加正式导出入口
2. 支持 `CSV / JSON` 两种导出格式
3. 支持按结果状态筛选导出
4. 支持导出：
   - 项目基础信息
   - 步骤整段结果
   - 结构化字段结果

这一轮先不做：

- Markdown 导出
- 自定义导出模板
- 字段拖拽排序
- 变量表全量导出重构
- 独立的批量项目表格视图

## Key Changes

### 1. 导出入口接到批量执行结果弹层

在现有批量执行结果弹层中新增导出动作区。

第一版入口固定包含：

- `导出 CSV`
- `导出 JSON`

导出入口只对当前这次批量执行结果生效，不做“历史运行结果导出中心”。

### 2. 导出结果范围与筛选

复用当前结果弹层已经有的结果状态分类，首轮导出支持：

- `全部`
- `成功`
- `失败`
- `已跳过`
- `被阻塞`
- `已停止`

导出时使用当前筛选条件，而不是额外再开一套复杂过滤器。

也就是说：

- 用户在弹层里切到 `成功`
- 点击 `导出 CSV`
- 导出的就是当前成功子集

### 3. 首轮导出数据结构

每一条导出记录至少包含这些基础列：

- `project_id`
- `project_name`
- `template_id`
- `template_name`
- `step_id`
- `step_name`
- `result_status`
- `result_message`

其中：

- `result_status` 对应当前批量运行状态
- `result_message` 对应当前汇总文案

### 4. 整段结果进入导出

如果当前结果项对应的步骤存在整段结果，则导出列新增：

- `step_output_raw`

规则：

- 从项目当前 `stepOutputs[stepId]` 读取
- 没有结果时输出空字符串

### 5. 结构化字段进入导出

如果该步骤定义了结构化字段，并且项目当前存在 `stepStructuredOutputs[stepId]`，则按字段展开列。

列命名规则固定为：

- `field.{fieldKey}`

例如：

- `field.subject_description`
- `field.style_keywords`
- `field.negative_prompt`

规则：

- 只导出当前步骤定义过的字段
- 没有值时输出空字符串
- 不导出未定义的额外 key

### 6. JSON 与 CSV 的结构

#### CSV

CSV 首轮采用扁平列结构：

- 一行一个项目步骤结果
- 所有字段平铺成列
- 结构化字段用 `field.` 前缀

#### JSON

JSON 首轮同样采用扁平对象为主，避免结构不一致：

```json
{
  "project_id": "...",
  "project_name": "...",
  "step_id": "...",
  "step_name": "...",
  "result_status": "success",
  "step_output_raw": "...",
  "field.subject_description": "...",
  "field.style_keywords": "..."
}
```

不做嵌套对象版和扁平版双轨。

### 7. 导出服务层

新增一个专门的导出构建服务，避免把扁平化逻辑塞进 UI 组件。

建议新增：

- `services/batchResultExportService.ts`

该服务至少负责：

- 从当前批量结果列表和项目/模板数据构造导出记录
- 收集结构化字段列
- 统一生成 CSV 文本
- 统一生成 JSON 文本

UI 层只负责：

- 当前筛选结果传入
- 点击导出
- 调用现有文件保存链路

### 8. 与现有结构化输出的关系

这轮不新增结构化输出规则，只消费现有结果：

- `stepOutputs`
- `stepStructuredOutputs`

所以导出增强的关键不是“再定义结构”，而是把已经存在的结构化结果真正拿出来用。

### 9. 暂不纳入首轮的内容

以下内容明确延后：

- 变量结果导出增强
- 项目页单步骤导出入口
- Markdown 导出
- 导出字段勾选面板
- 批量运行结果再次重跑入口
- 导出模板保存

原因是首轮要先把“从批量结果弹层稳定导出整段+字段结果”打通。

## Test Plan

- 批量执行结果弹层能看到：
  - `导出 CSV`
  - `导出 JSON`
- 在不同筛选条件下导出：
  - `全部`
  - `成功`
  - `失败`
  - `已跳过`
  - `被阻塞`
  - `已停止`
  导出结果与当前筛选一致
- 若步骤有整段结果：
  - `step_output_raw` 正确导出
- 若步骤有结构化字段：
  - `field.{fieldKey}` 列正确生成
  - 字段值为空时导出空字符串
- 若步骤没有结构化字段：
  - 不产生无意义字段列
- CSV 内容能正常打开，不因换行或逗号导致错列
- JSON 内容结构稳定
- 不回归：
  - 现有批量执行
  - 现有结果筛选
  - 现有结构化输出阶段 A/B
- 至少完成：
  - `services/batchResultExportService.ts`
  - `components/project-runner/ProducerRunProgressModal.tsx`
  - `App.tsx`
  - 整仓 `tsc --noEmit`

## Assumptions

- 首轮导出只作用于当前批量执行结果，不追溯历史运行记录。
- 首轮只做 CSV / JSON，不做 Markdown。
- 首轮只导出项目基础信息、整段结果、结构化字段，不扩变量导出。
- 当前筛选状态直接决定导出范围，不额外加第二套筛选器。
