# PromptWordSplicer 代码架构优化实施方案

制定日期：2026-05-06
对应输入：

- [代码架构与优化调查报告.md](/E:/Project/Vscode/PromptWordSplicer/docs/代码架构与优化调查报告.md:1)

## 1. 方案目标

本方案不以“继续加功能”为目标，而是以“降低后续改动成本”为目标，优先解决以下问题：

1. `App.tsx`、`TemplateEditor.tsx`、`ProjectRunner.tsx` 过大且职责混杂
2. 插值逻辑、textarea 逻辑和模型执行逻辑存在重复或分散
3. 持久化、导入校验、错误反馈缺少统一约束
4. 当前已经出现 `domain/`、`services/`、`components/common/` 新结构，需要收敛为稳定目录规范

## 2. 实施原则

### 2.1 先收口，再扩展

当前工作区已经存在如下重构痕迹：

- [domain/projectDomain.ts](/E:/Project/Vscode/PromptWordSplicer/domain/projectDomain.ts:1)
- [domain/templateDomain.ts](/E:/Project/Vscode/PromptWordSplicer/domain/templateDomain.ts:1)
- [services/interpolationService.ts](/E:/Project/Vscode/PromptWordSplicer/services/interpolationService.ts:1)
- [services/executionAvailability.ts](/E:/Project/Vscode/PromptWordSplicer/services/executionAvailability.ts:1)
- [services/providerExecution.ts](/E:/Project/Vscode/PromptWordSplicer/services/providerExecution.ts:1)
- [services/schemas.ts](/E:/Project/Vscode/PromptWordSplicer/services/schemas.ts:1)
- [components/common/AutoResizeTextarea.tsx](/E:/Project/Vscode/PromptWordSplicer/components/common/AutoResizeTextarea.tsx:1)

因此这次优化不应再新增第二套平行结构，而应当把这些新增文件变成正式入口。

### 2.2 小步迁移，保证每一步都可运行

每个阶段都应满足：

- `npm run build` 可通过
- 不同时修改过多业务行为
- 优先做“搬迁 + 复用”，再做“行为调整”

### 2.3 纯函数先行

优先把以下逻辑抽成纯函数：

- 插值
- 变量同步
- 模板归一化
- 执行可用性判断
- 导入数据校验

这样后续才适合补测试。

## 3. 目标结构

建议收敛到以下结构：

```text
components/
  common/
    AutoResizeTextarea.tsx
  template-editor/
  project-runner/
  file-library/
domain/
  projectDomain.ts
  templateDomain.ts
services/
  interpolationService.ts
  executionAvailability.ts
  providerExecution.ts
  apiConnectivityService.ts
  ioService.ts
  schemas.ts
hooks/
  useAppPersistence.ts
  useAppState.ts
```

说明：

- `domain/` 放纯业务规则
- `services/` 放 I/O、模型执行、校验、插值等跨组件能力
- `components/common/` 放纯复用 UI
- `hooks/` 放和 React 生命周期绑定的编排逻辑

## 4. 分阶段修改方案

## Phase 0：收口当前重构痕迹

### 目标

先确认“哪些新文件是正式方案的一部分”，避免后续在旧文件和新文件之间来回横跳。

### 修改内容

1. 明确 [services/modelService.ts](/E:/Project/Vscode/PromptWordSplicer/services/modelService.ts:1) 的角色  
   建议改成薄门面文件，只 re-export：
   - `resolveStepExecutionAvailability` from `executionAvailability`
   - `executeModelText` from `providerExecution`

2. 明确 [domain/projectDomain.ts](/E:/Project/Vscode/PromptWordSplicer/domain/projectDomain.ts:1) 与 [domain/templateDomain.ts](/E:/Project/Vscode/PromptWordSplicer/domain/templateDomain.ts:1) 为正式归属  
   不再把相同逻辑保留在 `App.tsx`。

3. 明确 [components/common/AutoResizeTextarea.tsx](/E:/Project/Vscode/PromptWordSplicer/components/common/AutoResizeTextarea.tsx:1) 为唯一公共实现  
   其他组件内联版本应逐步删除。

### 验收标准

- 目录职责在文档中固定
- 没有第二套同职责的新文件继续出现

## Phase 1：完成 P1 级结构整理

### 目标

解决当前最明显的重复和过重问题，但不改变产品行为。

### 任务 1：统一插值服务

涉及文件：

- [App.tsx](/E:/Project/Vscode/PromptWordSplicer/App.tsx:159)
- [components/ProjectRunner.tsx](/E:/Project/Vscode/PromptWordSplicer/components/ProjectRunner.tsx:176)
- [services/interpolationService.ts](/E:/Project/Vscode/PromptWordSplicer/services/interpolationService.ts:1)

实施方式：

1. 以 `services/interpolationService.ts` 为唯一实现
2. 暴露统一入口，例如：
   - `interpolateProjectText(project, template, text)`
   - `extractVariableKeys(text)`
3. 删除 `App.tsx` 内的 `createInterpolator`
4. 删除 `ProjectRunner.tsx` 内的局部 `interpolate`

验收标准：

- 项目运行、导出、右侧预览使用同一套插值规则
- 代码库中不再存在第二份插值实现

### 任务 2：下沉领域逻辑

涉及文件：

- [App.tsx](/E:/Project/Vscode/PromptWordSplicer/App.tsx:38)
- [domain/projectDomain.ts](/E:/Project/Vscode/PromptWordSplicer/domain/projectDomain.ts:1)
- [domain/templateDomain.ts](/E:/Project/Vscode/PromptWordSplicer/domain/templateDomain.ts:1)

实施方式：

1. 将以下逻辑迁出 `App.tsx`：
   - `syncProjectVariables`
   - `markStepOutputMeta`
   - `appendStepRunLog`
   - `normalizeTemplate`
   - `normalizeProject`
2. `App.tsx` 只保留编排调用

验收标准：

- `App.tsx` 行数明显下降
- 领域逻辑都有独立导出函数

### 任务 3：统一 AutoResizeTextarea

涉及文件：

- [components/common/AutoResizeTextarea.tsx](/E:/Project/Vscode/PromptWordSplicer/components/common/AutoResizeTextarea.tsx:1)
- [components/TemplateEditor.tsx](/E:/Project/Vscode/PromptWordSplicer/components/TemplateEditor.tsx:31)
- [components/ProjectRunner.tsx](/E:/Project/Vscode/PromptWordSplicer/components/ProjectRunner.tsx:35)
- [components/PromptEditor.tsx](/E:/Project/Vscode/PromptWordSplicer/components/PromptEditor.tsx:14)
- [components/Sidebar.tsx](/E:/Project/Vscode/PromptWordSplicer/components/Sidebar.tsx:29)

实施方式：

1. 把公共 props 固化为：
   - `value`
   - `onChange`
   - `readOnly`
   - `minHeight`
   - `className`
2. 逐个替换旧实现
3. 删除各组件内联版本

验收标准：

- 只保留一个公共 textarea 实现
- 组件文件体量同步下降

## Phase 2：补齐持久化和导入边界

### 目标

把“能跑”提升到“更稳”。

### 任务 4：持久化防抖与错误提示

涉及文件：

- [App.tsx](/E:/Project/Vscode/PromptWordSplicer/App.tsx:327)
- 新增 `hooks/useAppPersistence.ts`
- [services/ioService.ts](/E:/Project/Vscode/PromptWordSplicer/services/ioService.ts:1)

实施方式：

1. 新增 `useAppPersistence`
2. 对 `projects/templates/settings` 的保存统一做 500ms 防抖
3. 将保存失败结果以 toast 或 modal 轻提示暴露给用户

验收标准：

- 高频输入不再每次都落盘
- 保存失败可见，不再只写控制台

### 任务 5：导入数据 schema 校验

涉及文件：

- [services/schemas.ts](/E:/Project/Vscode/PromptWordSplicer/services/schemas.ts:1)
- [services/ioService.ts](/E:/Project/Vscode/PromptWordSplicer/services/ioService.ts:1)
- [components/FileLibrary.tsx](/E:/Project/Vscode/PromptWordSplicer/components/FileLibrary.tsx:118)
- [components/MergeModal.tsx](/E:/Project/Vscode/PromptWordSplicer/components/MergeModal.tsx:1)

实施方式：

1. 以 `schemas.ts` 为中心建立运行时校验
2. 导入流程统一变成：
   - 读文本
   - `JSON.parse`
   - schema 校验
   - domain 归一化
   - 写入状态

验收标准：

- 非法 JSON、结构缺失、旧字段不匹配都有明确错误提示
- `ioService` 不再向上层返回裸 `any`

职责边界：

- 状态层负责项目、模板、设置和 UI 状态

### 任务 9：模型执行服务定型

验收标准：

## 5. 建议执行顺序

建议按以下顺序推进，而不是并行乱改：

1. Phase 0：收口当前重构痕迹
2. Phase 1：插值、domain、公共 textarea
3. Phase 2：持久化和 schema
4. Phase 3：拆大组件
5. Phase 4：状态层和模型服务定型
6. Phase 5：测试、脚本、命名清理

原因：

- 前两阶段风险最低，收益最大
- 第三阶段会移动大量 JSX，应在公共逻辑稳定后再做
- 状态层应在结构边界清晰后再引入

## 6. 里程碑与验收

### M1：基础收口完成

满足以下条件即可：

- `App.tsx` 不再保留核心 domain 纯函数
- 插值逻辑只有一份
- AutoResizeTextarea 只有一份

### M2：稳定性边界完成

满足以下条件即可：

- 持久化有防抖
- 导入有 schema 校验
- 保存失败有用户可见反馈

### M3：结构整理完成

满足以下条件即可：

- `TemplateEditor.tsx` 和 `ProjectRunner.tsx` 不再是 700+ 行级别
- `App.tsx` 明显退化为装配层
- 目录职责稳定

### M4：工程化达标

满足以下条件即可：

- 有 `typecheck` / `lint` / 基础测试
- 关键纯函数有测试覆盖

## 7. 风险与规避

### 风险 1：边重构边改功能，导致行为漂移

规避方式：

- P1 阶段只做搬迁和复用，不改业务规则

### 风险 2：组件拆分过早，反而增加沟通成本

规避方式：

- 先抽公共逻辑，再拆 JSX 大组件

### 风险 3：新旧服务并存时间过长

规避方式：

- 通过 `modelService.ts` 门面短期兼容
- 每完成一个迁移点，就删除旧实现

## 8. 最终建议

如果只选一个切入口，优先从这三件事开始：

1. 统一 `interpolationService`
2. 完成 `domain/` 下沉
3. 统一 `AutoResizeTextarea`

这三项做完以后，后续不管是拆大组件、补测试，还是引入状态层，都会容易很多。
