# 变量提取工具功能设定

## 模板提取预设

模板可以定义多个通用提取预设。每个预设包含名称、一个原始文本变量、多个目标变量、可选的 AI 补全模型变量，以及可选的整体提取说明。

项目运行时，如果变量被某个预设设为原始文本变量，应在该变量旁提供提取入口。点击入口打开变量提取标签并选中对应预设；一个变量关联多个预设时先由用户选择。预设模式读取项目变量内容作为原文，并锁定目标变量与模型配置，但提取结果仍需用户确认后写入。

原有手动输入、手动选择目标变量的流程作为“临时提取”模式继续保留。预设与临时模式的运行草稿按“项目 ID + 预设 ID”隔离，避免多项目或多预设并发时互相覆盖。

## 1. 功能定位

“变量提取”是项目运行页侧边栏中的通用结构化信息提取工具。

用户向工具粘贴任意文本，选择需要填充的项目变量，工具先进行本地规则匹配，再使用 AI 补全规则无法可靠提取的字段。提取结果必须经过用户确认后，才可以写入项目变量。

该工具不绑定特定模板、步骤、变量名称或业务流程。不得在实现中写死“全文本”“英文名”“主题”等字段。

典型工作流：

```text
粘贴或输入原始文本
-> 选择目标变量
-> 本地规则提取明确字段
-> AI 补全剩余字段
-> 用户检查和编辑结果
-> 确认写入项目变量
```

## 2. 设计原则

- **通用**：目标字段来自当前项目关联模板中的可编辑变量，不依赖固定变量名称。
- **结构化**：规则层和 AI 层都必须产出以变量 ID 为键的结构化结果。
- **不编造**：原始文本无法支持的字段应返回未提取，不允许凭空补充。
- **先规则后 AI**：明确匹配优先在本地完成；AI 默认只处理规则未成功提取的字段。
- **用户确认后写入**：任何提取结果都不能直接覆盖项目变量。
- **保护已有内容**：已有值默认不勾选覆盖；空变量默认勾选写入。
- **兼容手动流程**：没有可用模型时，工具仍可以执行本地规则提取。
- **保护常量**：模板常量变量不可选择、不可提取、不可写入。
- **尊重排除配置**：模板中标记为不参与提取的变量，不显示为目标字段，也不能由提取工具写入。

## 3. 侧边栏交互

项目运行页侧边栏增加“变量提取”一级标签，与现有“变量配置”“步骤导航”“导出烘焙”处于同一级别。

“变量提取”拥有独立的侧边栏内容区，不放进“变量配置”标签内部，也不设计成变量表中的可折叠区。用户切换标签时，原始文本、目标变量选择和提取结果在当前项目会话中保持。

侧边栏一级标签建议顺序：

```text
变量配置
步骤导航
变量提取
导出烘焙
```

“变量提取”标签内部按执行流程从上到下组织：

```text
原始文本
目标变量
模型与提取操作
提取结果确认
```

### 3.1 输入区

- 一个多行原始文本输入框。
- 输入内容是临时工具状态，不自动写入项目变量。
- 输入内容、目标变量选择、模型选择和提取结果按项目 ID 保存在当前应用会话内；切换侧边栏标签或项目标签后再回来不应丢失。
- 会话草稿不写入 `Project` 数据，不进入备份 JSON。
- 提供“清空”操作。
- 切换到其他侧边栏标签时不清空内容。

### 3.2 目标变量

- 显示当前项目关联模板中的所有非 `const` 且未禁用提取的输入变量。
- 默认选择全部可编辑变量。
- 用户可以单独选择或取消变量。
- 已经有值的变量需要显示“已有内容”状态。
- 模板常量变量不显示为可选目标。
- 模板中设置为“不参与提取”的变量不显示为可选目标。

### 3.3 模型选择

- 用户可以选择一个当前模板的模型变量。
- 默认优先使用模板中第一个可用模型变量。
- 没有可用模型时，显示“仅使用规则提取”，但不禁用提取按钮。
- 模型不可用时，需要显示具体原因，例如未配置 API Key、提供商禁用或模型预设失效。

### 3.4 执行按钮

按钮名称为“提取变量”。

执行顺序：

1. 校验存在原始文本和已选择的目标变量。
2. 执行本地规则提取。
3. 如果存在规则未提取字段，并且模型可用，则请求 AI 补全。
4. 合并结果并打开结果确认区。

## 4. 变量提取配置

模板输入变量在现有字段基础上增加以下可选配置：

```ts
interface TemplateInput {
  id: string;
  label: string;
  defaultValue?: string;
  isConst?: boolean;
  extractionDescription?: string;
  extractionDisabled?: boolean;
}
```

字段含义：

- `extractionDescription`：告诉 AI 应该从文本中提取什么，以及结果格式要求。
- `extractionDisabled`：设为 `true` 时，该变量不参与提取工具，不会出现在目标字段列表中。

默认值：

- 未设置提取说明时，使用变量名称作为最低限度的字段说明。

旧模板不需要数据迁移；缺少这些字段时按默认值运行。

## 5. 第一层：本地规则提取

本地规则层只负责识别明确结构，不进行语义猜测。

### 5.1 支持格式

至少支持以下输入：

```text
主题：街头魔术
英文名: Street Magic
背景提示 = 霓虹灯下的街道
```

```json
{
  "主题": "街头魔术",
  "英文名": "Street Magic"
}
```

```markdown
## 主题
街头魔术

## 英文名
Street Magic
```

### 5.2 匹配依据

规则层按以下顺序匹配：

1. 变量名称。
2. JSON 对象中的同名字段。

规则结果必须转换为以变量 ID 为键的结构：

```json
{
  "input_theme_id": {
    "value": "街头魔术",
    "source": "rule",
    "confidence": "certain"
  }
}
```

### 5.3 规则层限制

- 只写入唯一且明确的匹配结果。
- 同一字段出现多个不同结果时，标记为冲突，不自动选择。
- 不根据相似字段名猜测。
- 不处理 `const` 变量。
- 不处理 `extractionDisabled` 变量。
- 规则成功提取的字段默认不再交给 AI 修改。

## 6. 第二层：AI 结构化补全

AI 默认只处理以下字段：

- 规则未匹配成功的字段。
- 规则匹配发生冲突的字段。
- 用户明确要求重新使用 AI 提取的字段。

### 6.1 系统提示词

程序统一生成以下系统提示词，不要求用户编写：

```text
你是一个结构化信息提取工具。

你的任务是根据目标字段列表，从用户提供的原始文本中提取对应内容。

规则：
1. 优先提取原文中明确存在的信息。
2. 可以组合、概括或转换原文已有信息，但不得加入原文没有的信息。
3. 提取结果应保留字段语义标签；如果原文中有“字段名：内容”这类结构，返回值也应包含“字段名：内容”，不要只返回内容部分。
4. 保留对目标字段有价值的细节，不要过度概括。
5. 每个结果只能使用提供的字段 ID。
6. 无法确定的字段返回 null。
7. 只返回符合指定结构的 JSON，不要添加解释、Markdown 或其他内容。
```

### 6.2 用户提示词

程序根据用户选择的目标变量动态生成：

```text
请从下面的原始文本中提取目标字段。

目标字段：
[
  {
    "id": "input_english_name",
    "name": "英文名",
    "description": "提取游戏的英文名称，不包含中文名称"
  },
  {
    "id": "input_theme_and_cup",
    "name": "主题和杯子",
    "description": "整合风格、杯子外观和杯子花纹，输出完整描述"
  }
]

原始文本：
<source>
这里是用户输入的原始文本
</source>

请返回：
{
  "values": {
    "input_english_name": "提取结果或 null",
    "input_theme_and_cup": "提取结果或 null"
  }
}
```

传给 AI 的字段列表只包含本次需要 AI 处理的目标字段。

### 6.3 AI 返回协议

标准返回结构：

```json
{
  "values": {
    "input_english_name": "Street Magic",
    "input_theme_and_cup": null
  }
}
```

处理要求：

- 优先使用模型接口支持的 JSON Schema 或结构化输出能力。
- 模型不支持结构化输出时，使用提示词约束并在客户端解析 JSON。
- 允许从 JSON 代码块中提取 JSON 作为兼容兜底。
- 只接受本次请求中存在的变量 ID。
- 忽略模型返回的额外字段。
- 非字符串且非 `null` 的值视为无效。
- JSON 无法解析时，不得写入任何 AI 结果，并显示可理解的失败原因。

## 7. 结果合并

规则层和 AI 层统一生成以下内部结果：

```ts
interface VariableExtractionResult {
  inputId: string;
  value: string | null;
  source: 'rule' | 'ai' | 'unresolved';
  status: 'ready' | 'conflict' | 'unresolved' | 'error';
  message?: string;
}
```

合并规则：

1. 规则层的明确结果优先。
2. AI 补全规则未解决的字段。
3. AI 不得覆盖规则已经明确提取的结果，除非用户主动重新提取该字段。
4. `null`、空字符串和无效结果统一视为“未提取”。
5. 同一个变量最终只保留一个待确认结果。

## 8. 结果确认与写入

提取完成后显示可编辑的结果确认区，至少展示：

- 是否写入。
- 变量名称。
- 当前值。
- 提取值。
- 来源：规则、AI 或未提取。
- 冲突与错误说明。

默认勾选规则：

- 当前变量为空且提取成功：默认勾选。
- 当前变量已有内容：默认不勾选。
- 未提取、冲突或错误：默认不勾选。

用户可以：

- 修改提取结果。
- 单独勾选或取消某个变量。
- 选择是否覆盖已有值。
- 确认写入。
- 取消并保留原始文本。

确认写入时：

- 使用变量 ID 更新 `project.inputValues`。
- 不允许写入 `const` 变量。
- 不允许写入 `extractionDisabled` 变量。
- 未勾选、空值、冲突和错误结果不写入。
- 写入后保持现有项目数据与 `project.variables` 兼容同步规则。

## 9. 状态与错误提示

工具需要区分以下状态：

- `仅规则提取`：没有可用模型，仅运行本地规则。
- `规则提取完成`：全部字段由规则明确提取。
- `AI 补全中`：规则执行完成，正在补全剩余字段。
- `部分提取成功`：部分字段未提取或发生冲突。
- `提取失败`：AI 请求或返回解析失败，但仍保留规则层已获得的结果。

错误提示必须说明具体原因，不能只显示“提取失败”。

## 10. 数据与隐私

- 原始文本默认只保存在当前界面临时状态中，不写入项目、不导出备份。
- 只有需要 AI 补全时，才将原始文本发送给选定模型提供商。
- 调用 AI 前需要在界面上明确显示当前模型。
- API Key 沿用现有全局模型设置，不写入模板和项目。
- AI 提取不写入步骤输出，也不创建步骤运行记录；后续若需要审计功能，再单独设计工具运行记录。

## 11. 不在首版范围内

- 不自动识别并采用步骤输出中的某一段方案。
- 不自动创建项目。
- 不在没有用户确认的情况下批量覆盖变量。
- 不支持从图片、文件附件或网页直接提取。
- 不允许用户为该工具编写任意系统提示词。
- 不将提取工具绑定到某个固定步骤或固定变量。

## 12. 实现位置建议

- `components/Sidebar.tsx`：增加与变量配置、步骤导航同级的“变量提取”一级标签。
- `components/VariableExtractionTool.tsx`：输入、变量选择、模型选择、结果确认 UI。
- `services/variableExtractionService.ts`：规则解析、AI 提示词构造、结果合并和校验。
- `services/aiTextService.ts`：复用现有文本模型请求能力，增加结构化输出兼容调用。
- `services/aiAvailabilityService.ts`：复用模型可用性判断。
- `components/TemplateEditor.tsx`：编辑变量智能提取说明。
- `components/TemplateEditor.tsx`：可以设置变量不参与提取。
- `types.ts`：提取配置和内部结果类型。
- `services/dataCompatibility.ts`：为旧模板补充兼容默认值。
- `docs/PROJECT_STRUCTURE.md`：登记功能位置和数据流。

## 13. 验收标准

1. 任意模板的可编辑变量都可以作为目标字段，不依赖固定名称。
2. 常见 `字段名：值`、JSON 和 Markdown 标题格式可以由规则层提取。
3. 没有配置模型时，规则提取仍可使用。
4. 规则已明确提取的字段不会被 AI 再次修改。
5. AI 只返回并写入有效的目标变量 ID。
6. AI 返回非法 JSON、额外字段或错误类型时不会污染项目数据。
7. 已有内容默认不覆盖，空变量默认勾选写入。
8. 用户确认前，项目变量不会发生变化。
9. `const` 变量不能选择或写入。
10. 标记为不参与提取的变量不能选择或写入。
11. 旧模板和旧项目无需迁移即可正常打开。
12. 完成实现后运行 `npm run build`。
