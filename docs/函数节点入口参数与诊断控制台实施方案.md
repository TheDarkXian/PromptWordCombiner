# 函数节点入口参数与诊断控制台实施方案

## 1. 实施目标

在不破坏旧模板运行的前提下，完成第一阶段“函数节点入口参数 + 静态诊断 + 底部问题面板”的闭环。

第一阶段完成后，用户应能做到：

1. 在函数节点里看到“入口参数”区。
2. 从函数体 `{{变量名}}` 一键同步入口参数。
3. 函数体引用未声明参数时，在底部“问题”面板看到错误。
4. 有入口参数声明的函数节点执行时，优先从入口参数解析值。
5. 旧节点没有入口参数声明时，继续按旧的全局插值逻辑运行。

本实施方案对应设计文档：

- [函数节点入口参数与诊断控制台方案.md](/E:/Project/Vscode/PromptWordSplicer/docs/函数节点入口参数与诊断控制台方案.md:1)

## 3. 数据模型实施

### 3.1 修改文件

- [types.ts](/E:/Project/Vscode/PromptWordSplicer/types.ts:1)
- [services/schemas.ts](/E:/Project/Vscode/PromptWordSplicer/services/schemas.ts:1)
- [domain/templateDomain.ts](/E:/Project/Vscode/PromptWordSplicer/domain/templateDomain.ts:1)

### 3.2 新增类型

建议新增：

```ts
export type StepParameterType = 'text' | 'table';

export type StepParameterSource =
  | { type: 'same_name'; key: string }
  | { type: 'project_input'; inputId: string; key: string }
  | { type: 'project_variable'; key: string }
  | { type: 'step_return'; stepId: string; key: string }
  | { type: 'literal'; value: string };

export interface StepParameter {
  id: string;
  name: string;
  type: StepParameterType;
  required?: boolean;
  source?: StepParameterSource;
}
```

并在 `TemplateStep` 上新增：

```ts
parameters?: StepParameter[];
```

### 3.3 normalize 规则

`normalizeTemplate` 或等价领域归一化逻辑中：

- 缺失 `parameters` 时保留 `undefined`，表示旧逻辑兼容模式。
- 存在 `parameters` 时过滤空 name。
- `required` 默认为 true。
- `type` 非 `table` 时默认为 `text`。
- `source` 非法时丢弃。
- `id` 缺失时生成稳定 id。

注意：不要在 normalize 时自动从函数体生成 parameters，否则旧项目会被动进入严格模式。

## 4. 函数体引用扫描服务

### 4.1 新增文件

建议新增：

- `services/stepParameterService.ts`

### 4.2 服务职责

提供以下纯函数：

```ts
extractStepParameterReferences(content: string): StepParameterReference[]
syncStepParametersFromContent(step: TemplateStep): StepParameter[]
normalizeStepParameter(parameter: Partial<StepParameter>): StepParameter | undefined
```

### 4.3 StepParameterReference

```ts
export interface StepParameterReference {
  raw: string;
  name: string;
  type: 'text' | 'table';
  fieldKey?: string;
  rowIndex?: number;
  valid: boolean;
  reason?: string;
}
```

### 4.4 扫描规则

文本引用：

```txt
{{角色名称}}
```

得到：

```ts
{ name: '角色名称', type: 'text', valid: true }
```

表引用：

```txt
{{角色表[0].角色名称}}
```

得到：

```ts
{
  name: '角色表',
  type: 'table',
  rowIndex: 0,
  fieldKey: '角色名称',
  valid: true
}
```

非法引用：

```txt
{{}}
{{角色表.name}}
{{角色表[].name}}
{{角色表[abc].name}}
```

返回 `valid: false`，交给诊断服务生成问题。

## 5. 参数来源解析

### 5.1 新增或扩展文件

建议新增：

- `services/stepParameterBindingService.ts`

### 5.2 核心函数

```ts
resolveStepParameterSource(
  parameter: StepParameter,
  project: Project,
  template: Template,
  currentStep: TemplateStep
): StepParameterResolvedValue
```

### 5.3 同名自动绑定

同步参数时，如果没有显式 source，先写入：

```ts
source: { type: 'same_name', key: parameter.name }
```

运行解析 `same_name` 时按顺序查找：

1. 上游函数返回值同名。
2. 项目变量同名。
3. 模板入口同名。
4. 项目局部变量同名。

V1 可以先不要求 UI 显示具体来源类型，只显示解析结果：

- `来源：同名变量`
- `来源：未绑定`

### 5.4 解析失败

如果参数 required 且无法解析值：

- 静态诊断里显示“入口参数未绑定来源”。
- 运行前阻止该函数节点执行。

## 6. 参数优先插值

### 6.1 修改文件

- [services/interpolationService.ts](/E:/Project/Vscode/PromptWordSplicer/services/interpolationService.ts:1)
- 运行调用处：重点检查 [components/ProjectRunner.tsx](/E:/Project/Vscode/PromptWordSplicer/components/ProjectRunner.tsx:1) 和自动执行相关服务。

### 6.2 新增函数

```ts
interpolateStepBody(
  step: TemplateStep,
  project: Project,
  template: Template
): InterpolationResult
```

返回：

```ts
interface InterpolationResult {
  text: string;
  diagnostics: StaticDiagnostic[];
}
```

### 6.3 兼容规则

- `step.parameters === undefined`：走旧 `interpolateText`。
- `step.parameters` 是数组：严格参数模式。

严格参数模式下：

- `{{参数名}}` 只从入口参数值中取。
- `{{表参数[0].字段}}` 只从入口参数表值中取。
- 未声明参数不直接读全局变量。
- 缺值返回诊断。

## 7. 静态诊断服务

### 7.1 新增文件

建议新增：

- `services/templateDiagnosticsService.ts`

### 7.2 类型

新增到 `types.ts`：

```ts
export interface StaticDiagnostic {
  id: string;
  level: 'error' | 'warning' | 'info';
  code: string;
  message: string;
  stepId?: string;
  target?: {
    kind: 'function_body' | 'parameter' | 'return_text' | 'return_table' | 'table_column';
    key?: string;
  };
}
```

### 7.3 核心函数

```ts
validateTemplate(template: Template, project?: Project): StaticDiagnostic[]
validateStepParameters(step: TemplateStep, context: DiagnosticContext): StaticDiagnostic[]
validateStepReturns(step: TemplateStep): StaticDiagnostic[]
```

### 7.4 V1 诊断项

错误：

- `UNDECLARED_PARAMETER_REFERENCE`：函数体引用了未声明入口参数。
- `INVALID_PARAMETER_REFERENCE`：函数体引用格式非法。
- `UNBOUND_PARAMETER`：入口参数找不到来源。
- `EMPTY_RETURN_NAME`：返回文本变量名为空。
- `EMPTY_TABLE_COLUMN_NAME`：返回表列变量名为空。
- `DUPLICATE_PARAMETER_NAME`：入口参数重名。
- `DUPLICATE_RETURN_NAME`：返回值重名。

警告：

- `UNUSED_PARAMETER`：参数声明了但函数体未使用。
- `LEGACY_PLACEHOLDER_IN_STRICT_STEP`：严格参数节点里仍使用 `<变量名>`。
- `NO_RETURN_DECLARED`：函数节点没有返回值。

## 9. 执行链路接入

### 9.1 手动运行

在执行函数节点前：

1. 调用静态诊断。
2. 如果当前 step 有 error，阻止执行。
3. 使用 `interpolateStepBody` 生成最终 prompt。
4. 执行模型调用或手动结果流程。

### 9.2 自动执行

自动执行候选筛选时：

- 有静态 error 的函数进入 blocked。
- blocked reason 使用诊断 message。

涉及文件：

- [services/stepGraphService.ts](/E:/Project/Vscode/PromptWordSplicer/services/stepGraphService.ts:1)
- [components/ProjectRunner.tsx](/E:/Project/Vscode/PromptWordSplicer/components/ProjectRunner.tsx:1)
- producer preflight 相关组件。

### 9.3 蓝图依赖

V1：

- 无 parameters 的节点继续用函数体引用推导。
- 有 parameters 的节点优先用 parameters 推导输入变量。
- 同名来源先按参数 name 推导。

后续再把 source 级别依赖纳入图计算。

## 11. 迁移策略

### 11.1 旧节点

旧节点没有 `parameters` 字段：

- 不显示强制错误。
- 可以显示轻提示：尚未启用入口参数。
- 运行仍使用旧插值。

### 11.2 用户主动启用

用户点击“同步函数体引用”后：

- 写入 `parameters`。
- 当前节点进入严格参数模式。
- 开始显示未声明、未绑定等诊断。

### 11.3 新建节点

建议新建函数节点默认：

- `parameters: []`
- 也就是默认严格参数模式。

如果担心切换过猛，可以先让新建节点仍为 undefined，等用户同步后启用。

推荐：新建节点默认严格，但提供清晰的“同步函数体引用”入口。

## 12. 风险控制

### 12.1 风险：用户觉得多了一步

缓解：

- 提供“一键同步函数体引用”。
- 参数区保持紧凑。
- 同名来源自动绑定。

### 12.2 风险：旧模板突然报错

缓解：

- 没有 `parameters` 的节点不启用严格模式。
- 文档和 UI 都说明“同步后启用入口参数”。

### 12.3 风险：诊断过多造成噪音

缓解：

- V1 只把真正阻塞运行的问题设为 error。
- 未使用参数、无返回值先用 warning。
- 问题面板支持按级别显示。

### 12.4 风险：参数来源解析与现有变量系统冲突

缓解：

- V1 同名绑定只作为解析策略，不立即重构全局变量系统。
- 保留旧 `inputValues`、`customInputs`、`variables`。
- 先在 `stepParameterBindingService` 中集中处理来源优先级。

## 14. 验收标准

### 功能验收

- 函数体写 `{{角色名称}}` 后，点击同步能生成入口参数 `角色名称`。
- 严格参数节点引用未声明参数会在“问题”面板报错。
- 参数重名会报错。
- 返回表列名为空会报错。
- 旧节点不启用 parameters 时仍可按旧逻辑运行。
- 有 parameters 的节点拼接时入口参数优先。

### 体验验收

- 入口参数区不显著挤压函数体空间。
- 问题面板可收起。
- 状态栏不干扰主工作区。
- 诊断文案能让用户知道该改哪里。

### 工程验收

- `typecheck` 通过。
- `test` 通过。
- `check:i18n:strict` 通过。
- `check:garbled` 通过。
- `build` 通过。
