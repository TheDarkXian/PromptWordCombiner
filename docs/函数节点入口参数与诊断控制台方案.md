# 函数节点入口参数与诊断控制台方案

## 1. 背景

当前项目已经开始从“提示词拼接器”转向“提示词函数流”：

- 函数节点有函数体。
- 函数节点可以返回文本或返回表。
- 变量表正在逐步纳入统一变量体系。
- 蓝图已经能通过变量引用推导上下游关系。

但输入侧仍然保留较多旧模型痕迹：函数体里直接写 `{{变量名}}`，系统会从项目变量、模板输入、上游输出等全局上下文里寻找值。这在使用体验上方便，但从“函数”语义看，等价于函数体直接读取全局变量。

如果要让节点真正像编程语言里的函数，就需要引入正式的入口参数。

目标语义应接近：

```ts
function 生成角色描述(角色名称, 角色背景, 角色表) {
  // 函数体只允许引用入口参数
  return 角色描述
}
```

而不是：

```ts
function 生成角色描述() {
  // 随便从全局变量里读取
  return {{角色名称}} + {{角色背景}}
}
```

## 2. 设计目标

1. 函数节点必须有清晰的入口参数。
2. 函数体中的 `{{...}}` 引用默认解释为入口参数引用，而不是全局变量引用。
3. 入口参数可以绑定到外部值来源，例如项目入口、项目变量、上游函数返回值。
4. 当入口参数与外部变量同名时，拼接时优先使用入口参数。
5. 函数体引用不存在的参数时，应产生静态错误。
6. AI 返回格式错误、解析失败等运行期问题，应进入控制台。
7. 工作区底部需要有类似 VS Code 的“问题 / 控制台 / 输出”面板承载诊断信息。
8. 旧项目需要兼容，不能因为引入严格参数模式导致旧模板立刻不可运行。

## 3. 术语统一

面向用户的术语建议如下：

| 概念 | 建议术语 | 说明 |
| --- | --- | --- |
| Step / 节点 | 函数节点 | 蓝图里的可执行单元 |
| Prompt content | 函数体 | 用户写提示词的主体区域 |
| 输入变量 / 模板变量 / 占位符 | 入口参数 | 函数节点声明的参数 |
| 输出变量 | 返回文本 | 函数返回的一段文本 |
| 表变量输出 | 返回表 | 函数返回的多行表数据 |
| 结构化字段 | 表列 | 返回表中的列 |
| 静态校验错误 | 问题 | 不运行 AI 就能发现的问题 |
| 运行期错误 / 解析错误 | 控制台错误 | 执行过程中产生的问题 |

内部代码命名建议：

```ts
StepParameter
StepParameterBinding
StepReturn
StaticDiagnostic
RuntimeDiagnostic
```

## 4. 核心语义

### 4.1 入口参数优先

如果函数节点声明了入口参数 `wqq`，函数体里写：

```txt
{{wqq}}
```

那么拼接时应优先读取该函数节点的入口参数 `wqq`，而不是直接去全局变量表里读 `wqq`。

这类似编程语言里的局部变量优先级。

用户侧可以称为“同名绑定”：

```txt
入口参数 wqq -> 来源：同名变量 wqq
```

不建议在界面里使用“遮蔽”“shadowing”等术语。

### 4.2 函数体只引用入口参数

严格模式下，函数体中的 `{{...}}` 必须对应入口参数。

合法：

```txt
请根据 {{角色名称}} 和 {{角色背景}} 生成角色描述。
```

要求当前函数节点声明：

```txt
入口参数：角色名称、角色背景
```

表参数引用：

```txt
请扩写 {{角色表[0].角色名称}}。
```

要求当前函数节点声明：

```txt
入口参数：角色表，类型为表
```

### 4.3 未声明引用是静态错误

如果函数体写：

```txt
请根据 {{角色背景}} 生成描述。
```

但入口参数里没有 `角色背景`，应报静态错误：

```txt
函数体引用了未声明入口参数：角色背景
```

这类错误不需要请求 AI，也不需要运行节点。

### 4.4 同名自动绑定

当用户同步入口参数时，系统可以自动寻找同名来源。

建议优先级：

1. 上游函数返回值同名。
2. 项目变量同名。
3. 模板入口同名。
4. 项目局部变量同名。
5. 找不到则标记为未绑定。

示例：

```txt
入口参数：角色名称
来源：项目入口 角色名称
```

```txt
入口参数：角色表
来源：函数「生成角色列表」返回表 角色表
```

## 5. 数据模型建议

### 5.1 StepParameter

```ts
export interface StepParameter {
  id: string;
  name: string;
  type: 'text' | 'table';
  required?: boolean;
  source?: StepParameterSource;
}
```

说明：

- `id` 用于稳定编辑和重命名。
- `name` 是用户看到的变量名，也是函数体 `{{name}}` 的引用名。
- `type` V1 只做文本和表。
- `required` 默认 true。
- `source` 描述参数从哪里取值。

### 5.2 StepParameterSource

```ts
export type StepParameterSource =
  | { type: 'same_name'; key: string }
  | { type: 'project_input'; inputId: string; key: string }
  | { type: 'project_variable'; key: string }
  | { type: 'step_return'; stepId: string; key: string }
  | { type: 'literal'; value: string };
```

V1 可以先主要落地：

- `same_name`
- `project_input`
- `project_variable`
- `step_return`

`literal` 可作为后续手动调试能力。

### 5.3 TemplateStep 扩展

```ts
export interface TemplateStep {
  parameters?: StepParameter[];
}
```

兼容规则：

- 没有 `parameters` 的旧函数节点走旧的全局变量解析逻辑。
- 有 `parameters` 的函数节点进入严格参数模式。

后续也可以在模板层增加：

```ts
functionParameterMode?: 'legacy_global' | 'strict_parameters';
```

但 V1 不一定需要模板级开关。

## 6. 入口参数 UI

函数节点面板中新增紧凑的“入口参数”区，位置建议放在函数体上方。

布局示例：

```txt
入口参数                         同步函数体引用
角色名称    文本    来源：同名变量
角色背景    文本    来源：项目入口
角色表      表      来源：生成角色列表.角色表
```

操作建议：

- `同步函数体引用`：扫描函数体里的 `{{...}}`，自动补齐缺失参数。
- `新增参数`：允许用户手动添加参数。
- `删除参数`：删除后若函数体仍引用该参数，立即产生静态错误。
- `重命名参数`：V1 可只改参数名，不自动改函数体；V2 再做同步重命名。
- `来源`：V1 先显示自动绑定结果；V2 再做完整来源选择器。

## 7. 引用扫描规则

### 7.1 基础引用

从函数体提取：

```txt
{{变量名}}
```

得到参数名：

```txt
变量名
```

### 7.2 表引用

从函数体提取：

```txt
{{角色表[0].角色名称}}
```

得到参数名：

```txt
角色表
```

并推断参数类型为 `table`。

### 7.3 非法引用

这些应进入静态诊断：

```txt
{{}}
{{角色表.name}}
{{角色表[].name}}
{{角色表[abc].name}}
{{角色表[0]}}
```

V1 可以先检查格式，V2 再检查表列是否存在。

## 8. 参数解析与拼接

新增专用拼接流程：

```ts
interpolateStepBody(step, project, template)
```

流程：

1. 判断函数节点是否有 `parameters`。
2. 如果没有，走旧的 `interpolateText` 兼容逻辑。
3. 如果有，进入严格参数模式。
4. 根据每个参数的 source 解析参数值。
5. 构造局部参数表：

```ts
const parameterValues = {
  角色名称: '阿洛',
  角色背景: '边境城邦的档案员',
  角色表: tableValue
};
```

6. 函数体 `{{...}}` 只从 `parameterValues` 中取值。
7. 未声明、未绑定、缺值时返回静态诊断或阻止运行。

## 9. 静态诊断

静态诊断是不运行 AI 就能发现的问题。

建议结构：

```ts
export interface StaticDiagnostic {
  id: string;
  level: 'error' | 'warning' | 'info';
  code: string;
  message: string;
  templateId?: string;
  stepId?: string;
  target?: {
    kind: 'function_body' | 'parameter' | 'return_text' | 'return_table' | 'table_column';
    key?: string;
  };
}
```

### 9.1 V1 静态错误

- 函数体引用了未声明入口参数。
- 入口参数未绑定来源。
- 必填入口参数解析为空。
- 表引用格式错误。
- 返回文本变量名为空。
- 返回表列变量名为空。
- 返回文本和返回表重名。
- 同一个函数内参数重名。

### 9.2 V1 静态警告

- 参数声明了但函数体未使用。
- 函数体仍使用旧 `<变量名>` 语法。
- 当前函数节点没有任何返回值。
- 多个函数返回同名变量，可能覆盖。

## 10. 动态诊断

动态诊断是运行时才知道的问题。

建议结构：

```ts
export interface RuntimeDiagnostic {
  id: string;
  level: 'error' | 'warning' | 'info';
  code: string;
  message: string;
  detail?: string;
  stepId?: string;
  timestamp: string;
}
```

### 10.1 动态错误类型

- 模型请求失败。
- 模型返回空内容。
- 多返回值函数返回的 JSON 不是对象。
- 缺少某个返回 key。
- 返回表不是数组。
- 返回表的行不是对象。
- JSON 解析失败。
- AI 返回了无法映射到声明返回值的数据。
- 上游函数失败导致当前函数无法解析参数。

### 10.2 动态警告类型

- 表字段缺失，被填为空字符串。
- 返回值存在额外字段，已忽略。
- 非字符串值被转成字符串。
- 运行结果覆盖了已有变量。

## 11. 底部面板设计

工作区底部增加可停靠面板，类似 VS Code。

标签：

- `问题`
- `控制台`
- `输出`

### 11.1 问题

显示静态诊断。

示例：

```txt
错误  生成角色描述  函数体引用了未声明入口参数：角色背景
错误  生成角色列表  返回表第 2 列变量名为空
警告  生成摘要      参数“风格”已声明但未使用
```

点击问题：

- 切换到对应函数节点标签。
- 聚焦到函数体、入口参数或返回值区域。

V1 可以先只做到切换函数节点。

### 11.2 控制台

显示运行日志和动态诊断。

示例：

```txt
[10:31:22] 开始运行：生成角色列表
[10:31:25] 错误：JSON 解析失败
[10:31:25] 原始返回：...
```

控制台应该支持：

- 清空
- 按级别过滤
- 按函数节点过滤

V1 可以只做展示和清空。

### 11.3 输出

显示当前函数或最近运行的输出。

内容包括：

- 返回文本
- 返回表预览
- 原始模型返回

V1 可先显示最近运行结果。

## 12. 状态栏设计

最底部增加状态栏，常驻一行。

示例：

```txt
2 错误  1 警告 | 当前函数：生成角色描述 | 参数 3 | 返回 2
```

交互：

- 点击错误/警告计数打开“问题”面板。
- 点击当前函数切换到函数标签。

V1 可以只显示计数和当前函数。

## 13. 蓝图关系

蓝图连线应从“函数体引用变量”逐步升级为“参数来源绑定”。

V1：

- 仍允许从函数体扫描引用推导依赖。
- 如果函数节点有 parameters，则使用 parameters 的 source 推导依赖。
- 同名绑定可以自动生成蓝图连线。

V2：

- 蓝图连线直接编辑参数来源。
- 从上游返回值拖到下游入口参数。
- 下游函数体不再直接决定连线，只决定参数是否被使用。

## 14. 兼容与迁移

### 14.1 旧项目

旧项目没有 `parameters`：

- 继续使用旧插值逻辑。
- 不立即产生“未声明参数”错误。
- 可以显示提示：此函数节点尚未启用入口参数。

### 14.2 新项目

新建函数节点建议默认启用 `parameters`：

- 函数体引用必须声明入口参数。
- 提供同步按钮降低维护成本。

### 14.3 半迁移状态

如果某函数节点有 `parameters`，就对该节点启用严格参数模式。

这样可以逐节点迁移，不需要整个模板一次性切换。

## 15. 分阶段实施计划

### Phase 1：入口参数与静态问题

目标：让函数节点真正拥有参数。

任务：

1. 新增 `StepParameter` 类型和 schema。
2. 新增函数体引用扫描服务。
3. 新增参数同步服务：从函数体生成入口参数。
4. 函数节点面板增加“入口参数”紧凑区。
5. 新增静态诊断服务。
6. 底部面板先实现“问题”标签。
7. 有 parameters 的节点启用严格参数检查。
8. 旧节点继续兼容旧插值。

验收：

- 函数体引用未声明参数会在“问题”中出现。
- 点击同步后能补齐入口参数。
- 删除参数后问题实时出现。
- 旧模板仍可运行。

### Phase 2：参数来源与同名绑定

目标：参数能稳定从外部取值。

任务：

1. 实现 `StepParameterSource`。
2. 实现同名自动绑定。
3. 参数区显示来源。
4. 拼接时入口参数优先。
5. 参数缺值时阻止运行并报错。
6. 蓝图使用参数来源推导依赖。

验收：

- 外部有同名变量时，入口参数自动绑定。
- 函数体 `{{wqq}}` 使用入口参数值。
- 找不到来源时，运行前阻止并显示问题。

### Phase 3：控制台与动态诊断

目标：运行期错误可见、可追踪。

任务：

1. 新增 RuntimeDiagnostic 数据结构。
2. 底部面板增加“控制台”。
3. AI 返回解析错误进入控制台。
4. 表返回解析警告进入控制台。
5. 模型请求失败进入控制台。
6. 支持清空控制台。

验收：

- JSON 解析失败能看到具体函数、错误和原始摘要。
- 表字段缺失能看到 warning。
- 控制台不再只依赖浏览器开发者工具。

### Phase 4：底部输出与跳转

目标：形成接近 IDE 的反馈闭环。

任务：

1. 底部面板增加“输出”。
2. 问题点击跳转到函数节点标签。
3. 控制台日志点击跳转到函数节点。
4. 状态栏显示问题计数、当前函数、参数数量、返回数量。

验收：

- 用户能从错误直接定位到对应函数。
- 最近运行输出能在底部查看。

### Phase 5：完善编辑体验

目标：降低参数维护成本。

任务：

1. 参数重命名自动更新函数体引用。
2. 返回值重命名自动更新下游参数来源。
3. 来源选择器支持手动选择项目变量、入口、上游返回。
4. 表参数支持列级校验。
5. 蓝图拖线直接绑定到入口参数。

验收：

- 重命名不容易打断依赖。
- 用户可以从 UI 明确控制参数来源。

## 16. 风险与取舍

### 16.1 不要一次性强制严格模式

如果旧模板突然全部要求声明入口参数，会破坏现有项目。

建议逐节点启用：

- 有 `parameters` 的节点严格。
- 无 `parameters` 的节点兼容。

### 16.2 不要一开始做复杂类型系统

V1 只做：

- text
- table

暂不做：

- number
- boolean
- object
- nested table

### 16.3 不要让用户理解过多内部来源类型

UI 上先显示：

```txt
来源：同名变量
来源：生成角色列表.角色表
来源：未绑定
```

内部再细分 `project_input`、`project_variable`、`step_return`。

### 16.4 静态错误和动态错误必须分开

静态错误是编辑期问题，应进“问题”。

动态错误是运行期问题，应进“控制台”。

两者混在一起会让用户不知道该修改函数体，还是重跑模型。

## 17. 推荐的最小实现闭环

建议下一步先实现：

1. `StepParameter` 类型。
2. 函数体引用扫描。
3. 函数节点面板“入口参数”区。
4. “同步函数体引用”按钮。
5. 静态诊断：未声明参数、未绑定参数。
6. 底部“问题”面板。
7. 有参数声明时，拼接走参数优先。

这组改动完成后，系统的核心心智会从：

```txt
提示词读取全局变量
```

变成：

```txt
函数节点声明参数，并通过参数获得外部值
```

这是后续蓝图连线、控制台、自动执行和类型系统继续发展的基础。
