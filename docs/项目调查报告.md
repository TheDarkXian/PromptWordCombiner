# PromptWordSplicer 项目调查报告

调查时间：2026-04-30  
调查分支：`集合AI`

## 1. 项目结论

这是一个完成度较高的桌面型提示词管理与拼接工具，核心定位不是“直接调用大模型生成内容”，而是“围绕模板、变量、步骤和项目实例，对提示词进行结构化编排、复用、拼接、导出和备份”。  
从代码结构、功能闭环和构建结果看，它已经超过了 demo 阶段，具备明确产品形态，适合个人或小团队在本地长期沉淀提示词资产。

## 2. 项目用途

项目的主要用途可以概括为四件事：

1. 定义提示词模板：把一套复杂提示词拆成多个步骤，每步可配置内容与变量占位符。
2. 基于模板创建项目：某个具体任务作为“项目实例”运行，项目持有自己的输入值、局部变量、步骤输出和覆盖内容。
3. 进行链式拼接：前一步的输出可以通过 `[[1]]`、`[[步骤名]]` 被后续步骤引用，形成提示词流水线。
4. 导出和沉淀资产：支持导出单项目烘焙结果、导出全量 JSON 备份、从备份恢复、以及增量合并外部数据。

从默认模板和界面文案判断，这个工具明显服务于“复杂创作提示词工作流”，尤其适合：

- AI 绘图提示词链
- 文案/策划分步提示词
- 游戏资产或角色设定生成前的提示词组织
- 个人提示词资产库管理

## 3. 技术栈与运行形态

项目采用 `React 19 + TypeScript + Vite + Tauri 2`：

- 前端入口与主状态集中在 [App.tsx](/E:/Project/Vscode/PromptWordSplicer/App.tsx:18)
- 类型定义在 [types.ts](/E:/Project/Vscode/PromptWordSplicer/types.ts:1)
- 构建配置在 [vite.config.ts](/E:/Project/Vscode/PromptWordSplicer/vite.config.ts:1)
- Tauri 应用配置在 [src-tauri/tauri.conf.json](/E:/Project/Vscode/PromptWordSplicer/src-tauri/tauri.conf.json:1)
- 本地存储与文件 I/O 封装在 [services/ioService.ts](/E:/Project/Vscode/PromptWordSplicer/services/ioService.ts:26)

运行形态有两层：

- 浏览器模式：通过 `localStorage` 持久化，文件导入导出走浏览器 API。
- Tauri 桌面模式：通过 `@tauri-apps/plugin-store`、`plugin-dialog`、`plugin-fs` 做本地存储和文件系统交互。

这说明作者有明确的“本地桌面工具”意识，而不是只写了一个网页壳。

## 4. 核心数据模型

项目围绕两类核心实体展开：

### 4.1 Template

定义见 [types.ts](/E:/Project/Vscode/PromptWordSplicer/types.ts:15)

- `id`
- `name`
- `inputs`
- `steps`
- `hideProjects`

模板相当于“提示词工作流蓝图”。其中：

- `inputs` 定义全局输入变量
- `steps` 定义步骤列表，每步有 `name`、`description`、`content`
- `hideProjects` 用于在资产库中隐藏该模板下的项目

### 4.2 Project

定义见 [types.ts](/E:/Project/Vscode/PromptWordSplicer/types.ts:1)

- `templateId`
- `name`
- `inputValues`
- `customInputs`
- `stepOutputs`
- `stepOverrides`
- `createdAt` / `lastModifiedAt` / `lastOpenedAt`

项目相当于“模板实例”。也就是说，模板负责定义结构，项目负责承载一次实际任务的数据和中间结果。

## 8. 调查中发现的现状与风险

### 8.1 项目核心价值在“组织与拼接”，不在“模型调用”

虽然 `package.json` 里保留了 `@google/genai` 依赖 [package.json](/E:/Project/Vscode/PromptWordSplicer/package.json:1)，`index.html` 里的 import map 也包含它 [index.html](/E:/Project/Vscode/PromptWordSplicer/index.html:33)，但当前业务代码中没有看到实际的 Gemini 调用链。  
这说明目前产品是“AI 前的提示词准备工具”，不是“AI 结果生成工具”。

### 8.2 存在旧痕迹或未清理配置

`index.html` 标题仍是 `Game Asset Prompt Splicer` [index.html](/E:/Project/Vscode/PromptWordSplicer/index.html:6)，与当前中文产品定位不完全一致。  
`metadata.json` 也表现出较明显的历史命名痕迹 [metadata.json](/E:/Project/Vscode/PromptWordSplicer/metadata.json:1)。

这说明项目可能经历过一次方向收束或产品重命名。

### 8.3 构建可以通过，但有一个静态资源提示

我在 2026-04-30 实测执行了生产构建，`vite build` 成功。  
但输出中有一条提示：

- `/index.css doesn't exist at build time, it will remain unchanged to be resolved at runtime`

这通常表示 `index.html` 里引用了 `/index.css`，但仓库内并没有对应产物或生成流程。它不一定阻塞运行，但属于应该确认的一项前端资源配置问题。

### 8.4 终端读取时出现中文乱码痕迹

在 PowerShell 调查过程中，多处中文文案显示为乱码。  
这可能是文件编码、终端编码页或历史拷贝导致的问题。单从静态读取无法断定运行时是否同样乱码，但这属于值得后续专项核查的一项工程风险，尤其涉及：

- 窗口标题
- 默认模板文案
- 各类按钮和弹窗文本

## 9. 建议的后续工作

如果后面你要继续打磨这个项目，我建议优先做这几件事：

1. 明确产品命名并统一清理遗留标识，包括 `index.html`、`metadata.json`、Tauri productName、窗口标题等。
2. 排查中文文案编码问题，确认仓库统一采用 UTF-8。
3. 核实 `index.css` 的来源，决定是补文件、改构建流程，还是删掉无效引用。
4. 清理未使用依赖，确认是否还需要 `@google/genai`。
5. 如果要增强产品能力，可以考虑加入“步骤一键复制”“模板标签/搜索”“项目归档”“模板版本历史”等更强的资产管理特性。
6. 如果要转向 AI 工作流工具，再考虑接入模型调用、执行日志、变量校验、步骤运行器等能力。
