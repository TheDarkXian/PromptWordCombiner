# 升级改进清单

## 目标

这份清单用于整理 PromptWordSplicer 当前阶段最值得继续投入的升级方向，按优先级分为：

- 必须做
- 应该做
- 可以做
- 暂缓

判断标准以当前产品定位为准：

- 单人高频使用
- 批量生成与批量执行
- 人工控制优先
- AI 执行作为工作流增强，而不是完全接管

## 必须做

### 1. TemplateEditor 清理与统一

当前模板编辑器已经承载了较多能力，但还存在这些问题：

- 术语和文案不完全统一
- 执行配置模板、模型引用、输出到变量等信息密度仍然偏高
- 历史编码和旧文案残留会影响维护

建议：

- 统一术语：模型引用、执行模板、输出到变量、步骤结果、运行记录
- 清理旧坏编码文案
- 继续压缩低频说明和次级操作
- 让高频动作优先围绕“编辑提示词、配置模型、查看步骤输出”

### 2. 批量结果导出增强

当前已经支持批量执行，但批量结果的利用链路还不完整。

建议：

- 支持按步骤导出真实输出结果
- 支持 `CSV / JSON / Markdown`
- 支持只导出成功项、失败项、未执行项
- 导出结果中带上项目名、模板名、步骤名、执行状态、输出内容

这是最符合产品核心场景的一项增强，因为你的主要使用模式就是“少量变量不同，大量内容相似”。

### 3. 结构化输出与输出拆变量

当前很多步骤仍然只能输出整段文本，再整体回填。

建议：

- 让步骤可以定义结构化输出字段
- 支持把一次结果拆成多个变量
- 让后续步骤引用字段级结果，而不是只能引用整段文本

例如可以拆成：

- 标题
- 描述
- 风格词
- 画面元素
- 负面词

这会直接提升模板复用性和批量生产稳定性。

## 应该做

### 4. 执行配置模板库第二版

第一版执行配置模板库已经能保存和应用模板，下一步值得补：

- 重命名模板
- 复制模板
- 最近使用排序
- 默认模板
- 模板启用状态更清晰

目标是把执行配置模板从“可用”推进到“真正形成资产沉淀”。

### 5. 变量自动补全增强

当前自动补全已经可用，但仍然偏基础。

建议：

- 增强变量搜索体验
- 显示更明确的来源标签
- 插入后高亮刚插入的变量
- 后续扩展到项目页高频输入区

### 6. 变量来源跳转

建议补上：

- 从 `{{variable}}` 直接跳到来源步骤
- 从结果变量跳到来源步骤
- 从步骤里快速查看当前引用了哪些上游结果

这个能力对长模板特别重要。

### 7. 模板版本快照

当前模板越来越像资产，而不是一次性文本。

建议：

- 模板保存时保留历史快照
- 能查看最近几个版本
- 能回滚到指定版本

这能明显降低“改坏模板”的风险。

## 可以做

### 8. 批量项目表格视图

现在已经有批量实例化和变量表导入导出，但还缺一个正式的批量项目管理视图。

建议：

- 用表格列出同模板下的全部项目
- 按变量、执行状态、失败原因筛选
- 直接在表格里查看关键步骤输出摘要

### 9. 失败项管理增强

批量执行现在已经能重跑失败项，后面还可以继续补：

- 按错误类型分组
- 只导出失败项
- 只重跑网络失败或模型失败
- 失败原因摘要

### 10. 步骤结果对比

同一步多次执行后，建议支持：

- 当前结果与上次结果对比
- 不同参数下输出差异对比
- 恢复某一次历史结果

### 11. 快捷键与高频操作优化

建议补：

- 执行当前步骤
- 复制当前结果
- 展开 / 收起步骤
- 切换紧凑 / 详细视图

## 暂缓

### 12. 节点画布

节点化画布可以作为后续方向，但当前不应优先。

原因：

- 会显著增加 UI 和状态复杂度
- 当前真实瓶颈不是编排形式，而是变量结构与批量生产效率

### 13. 多人协作与云同步

当前产品主要服务你自己的高频使用，先做多人协作和云同步会让产品显著变重。

### 14. 模板市场与插件系统

这类能力更适合在模板资产、批量生产和结构化输出稳定之后再考虑。

### 15. 全自动 Agent 编排

当前更合适的方向仍然是：

- 人工控制
- AI 增强
- 半自动串行执行

而不是直接进入复杂的自主编排和分支决策。

## 推荐执行顺序

如果按当前产品阶段继续推进，建议顺序如下：

1. TemplateEditor 清理与统一
2. 批量结果导出增强
3. 结构化输出与输出拆变量
4. 执行配置模板库第二版
5. 变量自动补全增强
6. 批量项目表格视图

## 结论

接下来最值得投入的主线，不是继续扩模型种类，而是：

- 提升模板维护效率
- 强化批量结果利用链路
- 让变量与步骤之间形成更稳定的结构化关系

如果只选三个最值得马上推进的方向，就是：

1. TemplateEditor 清理与统一
2. 批量结果导出增强
3. 结构化输出与输出拆变量
